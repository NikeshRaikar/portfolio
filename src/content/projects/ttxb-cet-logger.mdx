## Problem Statement

Commercial automotive dual-bus data loggers that capture both **CAN / CAN FD** and **Automotive Ethernet** simultaneously are expensive, tightly locked to proprietary Windows tooling, and difficult to script into headless CI/CD test benches.

**TTxB (ceT-logger)** was built from first principles to provide a transparent, scriptable, Linux-native logging appliance running on off-the-shelf Raspberry Pi 5 hardware.

## System Architecture

```text
[ Vehicle / Test Bench ]
   ├── CAN / CAN FD Bus ──────► SocketCAN Interface (can0 / can1)
   └── Automotive Ethernet ───► 100BASE-T1 Media Converter ► eth0
                                         │
                                         ▼
                        ┌─────────────────────────────────┐
                        │   TTxB (ceT-logger) Daemon      │
                        │  • Monotonic timestamping       │
                        │  • Ring-buffer capture engine   │
                        │  • systemd watchdog & rotation  │
                        └─────────────────────────────────┘
                                         │
                                         ▼
                      [ Structured Logs / PCAP / ASC ]
```

## Key Engineering Decisions

1. **Native Linux Interfaces:** Leveraging `SocketCAN` and standard packet sockets eliminates proprietary kernel drivers and makes integration with existing automation scripts effortless.
2. **Debian Packaging (`.deb`):** Instead of manual shell-script installation, the entire service, configuration templates, and `systemd` unit files are packaged into a reproducible `.deb` archive.
3. **Resilient Storage Handling:** Automated log rotation and clean shutdown hooks prevent trace corruption during sudden ignition-off power cycles on the bench.

## Outcome

TTxB enables rapid deployment of reproducible logging nodes across multiple test benches at a fraction of commercial hardware costs, while remaining fully inspectable and extensible via GitHub.
